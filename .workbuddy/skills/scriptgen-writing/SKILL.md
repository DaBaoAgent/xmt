## 铁律一：贴对标原句改写，不要另起炉灶

用户原话（两次强调）：

> 「我给你的稿子就是我喜欢的稿子，你就按照原来人家的稿子写，就是把大概的意思给改了就可以了」
> 「不是要一模一样的，是要把它的相近的词替换一下」
> 「不要把大幅度的都给我删改了」

### 怎么做

1. **保留对标每一句的句式骨架、语序、节奏**，一句对一句
2. **每个词都要换成我们的近义表达** —— 只换地点、只改个别词会被退回，**不能出现照抄原词的句子**
3. 只做三类最小改动：① 换同义词/近义词 ② 调位置 ③ 替换我们没有或不能说的内容
4. **禁止**大删大改、禁止换成自己另一套话术、禁止「重新构思」

### ★ 长度贴对标，不贴人设区间

对标 21 秒就写 21 秒，**不要凑到人设下限**。做法是**一句对一句，不加不减**：

- 不补展厅细节（「有位阿姨跟我说…」）
- 不补「我是某某，在苏州阳光大厦…」
- 不补结尾话术

做完对比 `我方时长 / 对标时长`，落在 **0.8-1.3 倍**即可。

> 踩过的坑：曾按人设区间凑，把对标 21 秒的稿子写成 54 秒（2.6 倍），被退回。
> 当时还硬塞了展厅门牌地址 + 「我是小冯」+ 两句顾客故事 —— 全是多余的。

### ★ 双人对话稿要分「正方/反方」，不能一方投降

对标是抬杠/互怼结构时，双方必须**对等**：
- 正方炫耀 → 反方泼冷水 → 正方再炫耀 → 反方再怼 …… 谁也不服谁
- **不能让一方问「那你倒是说说它哪儿好」然后另一方开始介绍产品** ——
  这叫投降 + 变推销，对抗就断了
- 收尾用「推出来遛遛」这种**挑起实战**的对白，比单方面介绍好

> 踩过的坑（029）：初版写成「顾客炫耀 → 店员教育 → 顾客服软」，
> 用户指出「应该是一个正方一个反方」。改成两个车主对等互怼后才对。

### ★ 不许问「弱智问题」：每句提问都要有真实顾虑

提问不能是给答案铺路的陪衬废话。**每一问都必须是一个真实用户会担心的场景**，
并且答句给出的事实/动作必须**直接消解这个顾虑**。

判定标准（三条全中才合格）：
1. **有信息增量** —— 换掉这一问，答案里的那个参数/动作就失去落点了，说明问对了；
   如果答案是「对，就是刚才说的那个」这种复述，说明是废话问
2. **不重复上一轮卖点** —— 同一篇里三个来回必须各打一个不同特点，不准换个问法再问一遍
3. **像人真的在挑刺** —— 带具体人/具体重量/具体时段（「我妈一百四十斤」「等红灯」「天黑才回」），
   而不是抽象的「会不会不好」「有没有问题」

反例（已被用户退回）：
- ❌ 心悦：摊子摆两边，推着不刮人？／小冯：错身也过得去，不用人家挪摊子。
  → 问的是上一句「车窄」的余味，答案是空转的「过得去」，没有任何新事实
- ❌ 跪半天，膝盖会不会麻？／垫子够厚，分量摊开，不硌骨头。
  → 与上一轮「跪垫是加厚海绵」同一卖点复读
- ❌ 一百五是怎么算的？／整架一起吃劲，坐上去压不弯。
  → 自问自答式解释，不解决任何使用顾虑

正例：
- ✅ 窄是窄，我妈一百四十斤，坐得下吗？／承重250斤，坐上去一点问题也没有。
- ✅ 整台多重，我一个人拎得动吗？／七点八公斤，一只手拎着上楼，不费劲。
- ✅ 照顾的人天天弯腰，腰受得住吗？／床面能升高，换垫子不用低头弯着干。

### ★ 答句口径（用户改定版 107，照这个抄手感）

答的人要像店里人跟顾客唠，**先给事实、再给一句让人省心的话**，不要光甩数字就完：

| 要 | 不要 |
|---|---|
| 车宽有**五十四厘米**，比轮椅还窄一点 | 车宽五十四 |
| **承重250斤**，坐上去一点问题也没有 | 座宽三十七点五，正常体型不卡腰 |
| 九寸实心胎，**您就放心开吧** | 九寸实心胎，压过去不陷，也不怕扎 |
| 手一松就停，断电也刹得住，**您不用一直盯着她** | 手一松就停，断电也刹得住 |

三条硬要求：
1. **问什么答什么** —— 问「坐得下吗」就答承重/座宽，别拐去讲别的卖点（答非所问比问错更让人烦）
2. **数字带单位** —— 「五十四厘米」「七点八公斤」「一百二十公斤」，不写裸数字
3. **句子留口语尾巴** —— 吧 / 呢 / 就行 / 不费劲 / 您放心，别写成说明书

> 用户原话：「不要问弱智的问题，不要答非所问」

### ★ 问句一律带语气词（用户 2026-10-24 定）

问句末尾必须有 **吗 / 呢 / 啊 / 吧**，不许光秃秃反问。

| 要 | 不要 |
|---|---|
| 这车能开吗？ | 这车能开？ |
| 胎会不会扎破呢？ | 胎会不会扎破？ |
| 护栏会不会挡手啊？ | 护栏挡不挡手？ |

光秃反问（「可以开？」）念出来像审问、像吵架，不像家属在打听事。

### ★ 四种「弱智」变体（2026-10-24 二次自查抓出来的，逐条比着改）

机器检查只查空转，查不出这四种，必须人工逐句过：

| 变体 | 例子（已退回） | 错在哪 | 改法 |
|---|---|---|---|
| 换卖点回答 | 问「瓷砖上会不会打滑」→ 答「底盘加宽、轮距拉开」 | 打滑是轮子抓地，稳是底盘，两码事 | 答案要落在同一个物理点：轮子大、着地实 |
| 讲座式答非所问 | 问「怎么劝我爸换床」→ 答「背慢慢起来，人就靠坐了」 | 问的是怎么劝，答的是床怎么动 | 答「让他自己按一下，觉得省事就肯了」 |
| 标题跑题 | 标题「那个坡推得上去吗」，全篇没一个坡 | 标题的痛点没进正文，观众觉得被骗 | 标题的痛点必须是第一问，且三问同一条线 |
| 裸问句/错前提 | 「后备箱占地方吗」；「这车比轮椅宽吧」 | 没人物没场景；47 公斤的人不会这么问，且前提是错的 | 加人物场景：「我家小车后备箱不大」；别先立个假前提再打自己 |

一条硬判据：**把答句单独拎出来，能不能看出它在回答哪一问？**看不出就是在换卖点糊弄。

### ★ 产品用法先对齐，别凭想象写（小福车事故 2026-10-24）

写「怎么用」之前先查 `docs/产品参数档案.md` 的用法段，别用「抬起来搁着」「悬空」这种想当然的动作。

小福车（单脚助行车）真实用法：
- 跪姿：**伤腿跪在跪垫上**，**好腿蹬地划行**推进
- 坐姿：**伤腿放在前面搁着**，**好腿滑行**推进

❌ 已被用户退回的错误写法：「伤腿不用跪，抬起来搁着，一路不沾地」
（错在：跪垫本来就是给伤腿膝盖承重的，抬起来就没法推了）

### ★ CTA 和地址跟着对标走

- 对标结尾是陈述句（「不用总麻烦人」「说停就停，说走就走」）→ **不加 CTA**
- 对标结尾是行动号召（「关注顾店长」）→ 保留一句，但**不写具体门牌地址**
- 拍摄提示里也不要写「字幕突出 XX 路 XX 号」

> 用户原话：「不一定每个脚本都要带地址」

### 词级替换范例

| 对标原句 | 改后 |
|---|---|
| 第一、第二… | 头一个、第二个… |
| 这都是我在评论区看到的 | 这话我天天能在评论区看到 |
| 大家可以上网搜一下这个轮组多少钱 | 你们上网查查那轮子就知道了 |
| 谁让你坐我新车的 | 你坐我车上了 |
| 之前还不知道 | 早先我还真不知道 |
| 从来没看到这么多的款式 | 这么多车我真是头回见 |
| 省心就选实心轮胎 | 图省事就挑实心的 |
| 只卖对的，不卖贵的 | 不卖贵的，只卖对的（调位置） |

## 铁律二：人设卡是硬约束

`config/personas.json`，**写稿前必读**，不能照搬对标的角色设定。

| id | 身份 | 时长/字数 | CTA 口径 |
|---|---|---|---|
| `oral` 口播号·翔哥 | 做了十年养老辅具、像邻居家懂行的朋友 | 60-90s / 260-400字 | **固定尾句：关注翔哥，了解更多辅具知识。** |
| `brand` 品牌号·心悦+小冯 | 心悦主讲、小冯实操，把客户最常问的问题演成一问一答 | 30-45s / 150-240字 | 到店试车/预约体验 |
| `personal` 个人号·小冯 | 工厂店/源头工厂经营者，朴实带本地口音；**现场只有拍摄 + 小冯两人** | **25-30s / 110-130字**（默认短平快；完整介绍才用 45-60s/200-280） | 来展厅看看/上门评估 |

**关键约束**：

- **★ 个人号短平快风格（2026-10-31 老板定，默认风格）**：约 **110-130 字 / 25-30 秒**（target_seconds=30），**6-7 句，一句一个信息点**，不铺垫不总结；用「您」当面讲，不要广告腔；参数只留记得住的（品牌、外观、1-2 个核心数字），备案型号、具体档位数值、折叠尺寸这类文字直接删；结尾落真实地点，不署名不喊口号。范本：SG-20261031-011「这台红色的助行器，一分钟说清」（113 字 / 26.9 秒）。只有用户明确要完整介绍时才回到 45-60s。
- **★ 个人号人称统一 A/B（2026-10-31 老板定）**：个人号对话稿的说话人只写 **A / B**，**A = 拍摄（不入镜、提问方）**、**B = 小冯（出镜、回答方）**。正文不要出现「拍摄：」「小冯：」这种称呼；单人口播稿不标说话人。tips/分镜里也用 A、B 指代，不写名字。
- **★ 个人号人数红线（2026-10-31 老板定）**：个人号现场只有两个人——**一个拍摄（不入镜，只出声提问）+ 一个出镜（小冯）**。脚本只允许两种形态：① 小冯单人口播；② 拍摄者提问、小冯回答。**严禁**三人以上同场、多人物小剧场、街采路人（张姐、老陈这类素人一律不许出现），也不许写「老周说……小冯说……」式的多角色对演；老周这类人只能由小冯在台词里转述。写之前先数人：超过两个人就是废稿。

- **对标的角色设定不能照搬**。对标是老人抬杠，我们是 20 岁店员 → 落在「替家里长辈挑车」上，不能写「您儿子推得动吗」「我推我妈上陡坡」
- **★ 品牌号 ≠ 必须双人**。人设卡的「心悦主讲、小冯实操」是**推荐形式**，不是硬约束 —— 用户明确说过「品牌号也可以一个人拍的」。同一对标已有单人版时，**直接移到品牌号即可，不要强行改写成对话**。只有当对标本身就是双人对话、且没有可复用的单人版时，才写对话稿。
- `brand` 人设明确 **心悦提问、小冯实操回答**（写对话稿时），不能反
- `brand` 人设要求「每条只讲一个客户真问题，**不堆功能点**」→ 质疑点最多留 2-3 个
- 主体是产品属性。对标是电动轮椅时，「推我妈」「老撞门」这类轮椅场景照抄会出戏

## 铁律三：时长口径

**目标时长必须落在人设区间内**，对标时长只做区间内的微调：

```python
target_duration = max(人设min, min(人设max, 对标时长))
```

即：対标在区间内 → 用对标；超上限 → 取上限；低于下限 → 取下限。

> ⚠️ 旧逻辑是 `max(lo*0.8, min(hi*1.2, 对标))`，会算出**人设区间外**的目标
> （品牌号 30-45s 配 15.6s 的对标 → 24s，比人设下限还短）。已修正。

查真目标：

```sql
SELECT code, target_seconds, estimated_seconds FROM sg_scripts;
```

**别按人设上限想当然压** —— 002 翔哥号目标 90 秒（对标 115.8 秒超出上限），
压到 55 秒就过头了。实际时长落在区间内即可。

## 铁律四：口语化

书面/术语词必须换大白话。常见对照：

副车架→架子 ／ 分量→有多重 ／ 碳钢→铁的 ／ 瞅见→看到 ／ 搁→放到
压得住→压得住(换句式) ／ 瞅瞅→看看 ／ 这么灵→这么利索 ／ 这声儿→这动静
样式→车 ｜ 稳当→笨重些 ｜ 控速→自己会慢下来 ／ 灵敏→灵 ／ 座宽→座位多宽
总宽度→整台车多宽 ／ 轮组→轮子 ／ 体验中心→看车的地方

**注意**：口语化时容易把价格词带回来（「查查那轮子多少钱」触发 `price` 规则）→ 改成「查查就知道了」。

## 铁律五：对话逻辑链

品牌号双人稿，**每句在对话链里有明确功能**（设前提 / 反驳 / 转场 / 收尾）。改词时要看功能，不能只换字面。

对标《皮皮熊抬杠》的咬合关系：
```
谁让你坐我新车的？→ 我自己也有 → 我这车下坡会控速
（潜台词：你坐我的新车 / 我自己也有车 / 所以我的车不溜）
```
第 1、2 句是**咬合**的。改第 1 句就必须同步调第 2 句。

**踩过的坑**：把「谁让你坐我新车的」改成「你这车，谁的呀」→ 问的对象从「你坐我的新车」变成「这车是谁的」，下一句「我自己也有」答非所问，用户反馈「读不通」。

**检查清单**：
- 第一个质疑后面必须有一句回应，不能只问不答
- 「您」「你」的人称要统一
- 主语不能跳（上一句说我的车，下句不能突然说对方的）
- 结尾 CTA 由人设指定的一方说（brand 是心悦）

## 铁律六：合规红线

`config/compliance.json`，高危规则一个不能碰：

| 规则 | 禁什么 |
|---|---|
| `efficacy_cure` | 治愈、根治、代替治疗、告别疾病 |
| `efficacy_guarantee` | 保证有效、百分百有效、无效退款 |
| `safety_guarantee` | 绝对安全、零风险、不会摔倒、永不侧翻 |
| `comparison` | 吊打、碾压、完爆、比别的品牌好 |
| `absolute` | 最好、最轻、最安全、首选品牌、独家 |
| `endorsement` | 专家推荐、医生都说、阿姨用了（效果好） |
| `price` | 具体价格、多少钱、报价、优惠 |
| `contact` | 加微信、二维码、电话咨询（**CTA 只能落展厅地址**） |
| `urgency` / `anxiety` | 最后一天、赶紧买、不买就后悔 |

还有一条硬规则：**产品动作类描述必须逐字回查知识库**。

> 曾把 F2Q 的折叠方式写成「两段一压一扣就拆开」——「两段」「一扣」都是编的。
> 知识库原文是「按钮往外一拉，一压完成折叠」（专利号 ZL2020 2 092755.4）。
> 观众看不出破绽，但属于编造。

## 人工定稿脚本模式

LLM 改稿在双人对话稿上极易跑偏（丢说话人、砍掉质疑点、对话断掉、时长在上下限之间来回摆）。
实在压不动就**人工写定稿**，用一次性脚本入库（参考 `tools/rewrite_all_align.py`）：

```python
body = {"format": "dialogue", "lines": [
    {"speaker": "心悦", "beat": "钩子", "text": "..."},
    {"speaker": "小冯", "beat": "回应", "text": "..."},
]}
body_text = body_plain_text(body)          # dialogue 会保留「说话人：」前缀
spoken = util.strip_speakers(body_text)     # 时长字数只算台词，不算前缀
wc = util.count_chars(spoken)
sec = util.estimate_seconds(spoken)
scan = compliance.scan_script(body_text, {"disclaimer": disclaimer}, "", FACT_TEXT, [])
```

**必带 `FACT_TEXT`**（数字溯源）：稿里报「19 公斤」时，知识库写的是「19 KG」，
不传事实片段会被 `numeric_unverified` 误判中危。

## 铁律七：产品参数必须先查档案，禁止凭印象和跨型号抄

**唯一参数来源**：`docs/产品参数档案.md`（在 xmt 项目里）。

写任何型号前，先在档案里找到对应条目，取「可写参数」和「禁写边界」。
档案里没有的型号，先按第 4 步查知识库补齐，**再写稿**。

```bash
.venv/Scripts/python.exe -c "
from scriptgen.company_kb import CompanyKB
kb=CompanyKB()
for h in kb.search('<型号> <品类>', top_k=8): print(h.get('doc_id'))
print(kb.read_text('<doc_id>', max_chars=6000))"
```

**三条高压线**：

1. **参数文档可能只写卖点不写数字** —— NIP 就是（承重/净重/尺寸全标「待补充」），
   真实数字要去 `marketing/` 和 `common/配文_*` 里找，多源交叉核对。
   `kb.read` 默认 max_chars 约 5K 会截断，长文档用 `offset=4000` 再读一段。
2. **竞品参数绝不抄** —— 对标杆子说的「16 公斤 / 12 公里 / 陀螺仪 / 大阻尼康复模式」
   是**他那台四合一代步车**的，跟我们任何产品都无关。
3. **手动款不写电动内容** —— NIP / 朋友2 / 减震款 / GB-819 / 小飞燕 全是手动款，
   稿里不能出现「电机/电池/摇杆/电磁刹车/瓦/AH/锂电/续航/遥控」。
   刹车要分清：NIP 和朋友2 是**手拉线刹**，只有 F2Q 和 P10 才是电磁刹车。

**踩过的坑**：小飞燕初稿误判成电动车（写了电机、摇杆、钥匙、电磁刹车）；
朋友2 混过减震款的 8.9KG/8档/7档；P10 和 F2Q 的公里数/瓦数互串过。

**写完自查**：把该产品稿扫一遍禁用词表，见档案第三节的自查命令。

## 铁律八：一键收尾，序号必须接续

改完稿，落库后跑**一条命令**（2026-10-23 起，替代原来的 5 处人工操作）：


自动完成：渲染源 md → 新 code 插进 `config/export_order.json` 同账号组末尾 →

三个产出一个都不能少（**Word 提词版已于 2026-10-24 停用**）：

| 产物 | 位置 |
|---|---|
| 源 md | `out/scripts/<日期>/<账号id>/<CODE>_<标题>.md` |
| 单独 TXT | `稿子/{账号}/<账号内序号>_<标题>.txt` |

- ⚠️ ORDER 已数据化到 `config/export_order.json`，不用再手改
  `export_standalone.py`；漏插的后果是 TXT 不出、账号内序号断档
- ⚠️ 标题别带标点：`slugify` 会把逗号/问号转成连字符，文件名带 `-` 会触发
  本机安全钩子拦（PermissionError），md 文件名同样受影响。标题一律用纯汉字+数字
- ⚠️ 归档时 `稿子/` 和 `对照表/` 要一起 `git add`（不在 .gitignore，历来漏提交）
- ⚠️ Word 已停出（`config/scriptgen.json` → `output.docx_enabled=false`）

## 踩坑清单

1. **另起炉灶写全新话术** → 用户明确否定，方向错了
2. **只换地点/个别词，其余照抄** → 用户退回「不是要一模一样的」
3. **照搬对标的角色设定** → 老人抬杠的话我们 20 岁店员说不出来
4. **只换字面不管逻辑链** → 对话读不通
5. **产品动作凭印象编** → 必须逐字回查知识库
6. **按人设上限压时长** → 应该跟对标时长走 80%-120%
7. **口语化时带回价格词** → 触发 `price` 规则
8. **改标题后不清旧文件** → out 目录混乱，容易点错
9. **抄对标的竞品参数** → 他说 16 公斤 / 12 公里，我们写 P10 必须用自己的 15.8 公斤 / 15 公里
